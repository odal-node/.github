# Support

**This project is pre-production and maintained by one person.** There is no support
contract, no SLA, and no paid tier that buys a faster answer. What follows is where a
question is most likely to be seen — not a promise about when.

## Where to ask

| You want to | Go to |
|---|---|
| Understand what the project does, or how to use a crate | [docs.odal-node.io](https://docs.odal-node.io) |
| Ask a question, or discuss an approach | **Discussions** on [dpp-core](https://github.com/odal-node/dpp-core/discussions) or [dpp-engine](https://github.com/odal-node/dpp-engine/discussions) |
| Report a bug | **Issues**, on the repository the bug is in |
| Request a feature | **Issues**, on the repository it belongs in |
| Report a security vulnerability | **security@odal-node.io** — never a public issue. See [SECURITY.md](SECURITY.md) |
| Ask about managed operation, or be told when it opens | [Join the waitlist](https://odal-node.io/waitlist) — it is an email, not a form |
| Anything else | **contact@odal-node.io** |

Ask in public where you can. A question answered in an issue or a discussion is
answered once and read many times; the same question by email is answered once.

## What makes a question answerable

- **Which repository and which version.** A commit SHA beats a version number, and both
  beat "the latest".
- **What you ran and what happened.** The actual command and the actual output, not a
  description of them.
- **What you expected instead**, and why — especially where a regulation is the reason
  you expected it. If you believe the software is wrong about EU law, cite the text you
  are reading it against. That is the most valuable category of report this project can
  receive.

## What this project cannot give you

- **Compliance advice.** Nothing here is legal advice, and no output of this software is
  evidence that you comply with anything. The software helps you assemble and sign a
  passport; whether the passport satisfies your obligations is between you, your
  notified body and your national authority.
- **Support for a deployment we do not operate.** Every node runs on its operator's own
  infrastructure. If your node misbehaves, we want the bug report — but we have no
  access to your system and no ability to look.
- **A conformance claim.** Where the code implements a standard, it says what it
  implements and what it does not claim. Read that statement before relying on it.

## The websites

`odal-node.io` and `docs.odal-node.io` carry documentation, schemas, vocabulary and
**demonstration** passports. They host no operator's live data and no production
service. Anything on those domains that resolves like a running node is a demonstration
of the format, not a service anyone's compliance depends on.

Real passports are served by the operator's own node, on the operator's own domain.
